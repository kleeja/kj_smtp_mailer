# برنامج إرسال البريد SMTP لكليجا

يُرسل بريد موقعك عبر خادم SMTP تملك التحكم به بدلًا من دالة `mail()` في PHP.
الرسائل المُرسَلة بهذه الطريقة تُصادَق بوصفها صادرةً عن صندوق بريد حقيقي، وهذا
ما يُبقي رسائل التسجيل واستعادة كلمة المرور بعيدةً عن مجلد البريد المزعج.

مبنيٌّ على [PHPMailer](https://github.com/PHPMailer/PHPMailer).

## التثبيت

نزّل الملف `kj_smtp_mailer-*.zip` المرفق بأحد [الإصدارات](../../releases)، ثم
ثبّته من **لوحة الإدارة ← الإضافات**. حزمة الإصدار تتضمن PHPMailer، أما النسخة
المستنسخة من هذا المستودع فلا تتضمنه؛ لأن المجلد `vendor/` يُبنى وقت إصدار الحزمة.

وإن أردت التشغيل من نسخة المستودع مباشرةً:

```bash
composer install --no-dev
```

## الإعدادات الجاهزة

**لوحة الإدارة ← إرسال البريد SMTP ← إعدادات جاهزة**

اضغط **استخدم هذه الإعدادات** في بطاقة شركة الاستضافة التي تستعملها، فيُضبط شطر
الخادم نيابةً عنك. وتطبيق أي إعداد جاهز **يستبدل مضيف SMTP والمنفذ والتشفير
والمصادقة الحالية**، ولا يمسّ بريد المُرسِل ولا اسم المستخدم ولا كلمة المرور.

والمصادقة مُفعّلة في كلا الإعدادين، لذا تبقى خطوة واحدة دائمًا: انتقل إلى
**لوحة الإدارة ← الإعدادات ← إرسال البريد SMTP**، وأدخل اسم المستخدم وكلمة المرور
الخاصين بصندوق البريد، ثم أرسل رسالة تجريبية إلى نفسك من تبويب **الحالة والاختبار**.

### Hostinger

| | |
| --- | --- |
| مضيف SMTP | `smtp.hostinger.com` |
| منفذ SMTP | `465` |
| تشفير SMTP | SSL |
| مصادقة SMTP | مُفعّلة |

استعمل حساب بريد أنشأته في لوحة hPanel (البريد الإلكتروني ← نطاقك). واسم المستخدم
هو العنوان كاملًا، مثل `noreply@yourdomain.com`.

### Gmail

| | |
| --- | --- |
| مضيف SMTP | `smtp.gmail.com` |
| منفذ SMTP | `587` |
| تشفير SMTP | TLS |
| مصادقة SMTP | مُفعّلة |

> [!NOTE]
> يجب تفعيل SMTP في حساب Gmail أولًا. وإذا كان التحقق بخطوتين مفعّلًا فلن تقبل
> Google كلمة مرورك المعتادة هنا، فأنشئ
> [كلمة مرور للتطبيقات](https://support.google.com/accounts/answer/185833)
> واستعملها بدلًا منها.

واسم المستخدم هو عنوان بريد Gmail كاملًا.

## الإعدادات

**لوحة الإدارة ← الإعدادات ← إرسال البريد SMTP**

| الإعداد | ملاحظات |
| --- | --- |
| بريد المُرسِل | العنوان الذي تصدر عنه الرسائل، وهو غالبًا صندوق البريد الذي تُصادِق به. |
| الإرسال دائمًا من هذا البريد | مُفعّل افتراضيًا، انظر *معالجة المُرسِل* أدناه. |
| اسم المُرسِل | الاسم الذي يظهر للمستلمين. |
| الإرسال دائمًا بهذا الاسم | مُفعّل افتراضيًا. |
| مضيف SMTP | مثل `smtp.gmail.com` |
| منفذ SMTP | اتركه فارغًا ليُستعمل المنفذ 465 مع SSL، و587 فيما عدا ذلك. |
| تشفير SMTP | `TLS` أي STARTTLS للمنفذ 587، و`SSL` للمنفذ 465. |
| مصادقة SMTP | لا تُعطّلها إلا مع خادم تمرير يقبل خادمك بحسب عنوان الـ IP. |
| اسم مستخدم SMTP وكلمة المرور | بيانات الدخول إلى صندوق البريد. |

ولصفحة **لوحة الإدارة ← إرسال البريد SMTP** تبويبان خاصان بها: *إعدادات جاهزة*
يضبط إعدادات الخادم لشركة استضافة معروفة، و*الحالة والاختبار* يبيّن ما إذا كان
البرنامج المساعد هو من يتولى بريد الموقع فعلًا، ويتيح لك إرسال رسالة تجريبية إلى
نفسك. تسلك الرسالة التجريبية المسار نفسه الذي يسلكه بريد الموقع الحقيقي، وإذا
رفضها الخادم عُرض سبب الرفض على مستوى SMTP في الصفحة نفسها.

### إضافة شركة استضافة أخرى

الإعدادات الجاهزة مُجمّعة في مصفوفة واحدة داخل `functions.php`:

```php
function kj_smtp_mailer_presets(): array
{
    return [
        'gmail' => [
            'name'   => 'Gmail',
            'values' => [
                'kj_smtp_mailer_smtp_host'       => 'smtp.gmail.com',
                'kj_smtp_mailer_smtp_port'       => '587',
                'kj_smtp_mailer_smtp_encryption' => 'tls',
                'kj_smtp_mailer_authentication'  => '1',
            ],
            'note'   => 'KJ_SMTP_MAILER_PRESET_NOTE_GMAIL',
        ],
    ];
}
```

أضف مُدخلًا جديدًا فيظهر في بطاقة خاصة به. وينبغي ألا يحمل الإعداد الجاهز سوى
القيم المشتركة بين جميع الحسابات على تلك الاستضافة، دون بيانات صندوق البريد نفسه.

والحقل `note` اختياري، ويأخذ مفتاحًا من `olang` يُعرض في البطاقة، ويُستعمل لكل ما
يلزم أن يفعله المدير لدى شركة الاستضافة قبل أن تعمل هذه الإعدادات.

## سلوكيات جديرة بالانتباه

**لا يتدخل حتى يعمل فعلًا.** ما لم يُضبط المضيف وبريد المُرسِل وبيانات الدخول
جميعًا، يترك البرنامج المساعد البريد وشأنه ويواصل كليجا استعمال `mail()`. وينطبق
هذا كذلك على غياب المجلد `vendor/`. وصفحة الحالة تُخبرك أيّ الحالتين أنت فيها.

**معالجة المُرسِل.** يُمرّر كليجا بريد مُرسِل مع كل رسالة يبعثها، وفي نموذج
الاتصال وبلاغات الملفات يكون هذا البريد بريد *الزائر* لا بريد الموقع. وتمرير
عنوان شخص آخر عبر صندوق بريدك يؤدي إلى إسقاط الرسالة لأسباب تتعلق بـ SPF/DMARC،
لذا يُرسل البرنامج المساعد افتراضيًا كل شيء من العنوان الذي ضبطته، ويضع العنوان
الأصلي في ترويسة `Reply-To`؛ فيظل الردّ على رسالة نموذج الاتصال واصلًا إلى
الزائر. ويمكنك تعطيل خياري «الإرسال دائمًا من...» إن كان خادم التمرير لديك يقبل
فعلًا أي مُرسِل.

**الإخفاقات ليست صامتة.** تُسجَّل الرسالة المرفوضة في سجل أخطاء PHP (وفي الملف
`cache/kleeja_log.log` عند تفعيل `DEV_STAGE`) مع سبب الرفض على مستوى SMTP وعنوان
مستلم مُقنَّع جزئيًا. أما متن الرسالة فلا يُسجَّل أبدًا؛ لأن كليجا يضع فيه كلمات
المرور المُولَّدة حديثًا وروابط التفعيل.

## إصدار نسخة جديدة

أنشئ وسمًا للإصدار وادفعه:

```bash
git tag v1.0 && git push origin v1.0
```

يتولى [سير عمل الإصدار](.github/workflows/release.yml) فحص الملفات، وتشغيل
`build.sh`، وإرفاق الحزمة بإصدار GitHub. ويمكن تشغيل `build.sh` محليًا كذلك:

```bash
./build.sh 1.0     # -> kj_smtp_mailer-1.0.zip
```

ويجب أن تُفَكّ الحزمة إلى مجلد اسمه `kj_smtp_mailer`؛ إذ يعتمد كليجا على اسم مجلد
البرنامج المساعد في ربط كل خطّاف من خطاطيفه.
